# 交互增强 V2：小小探索室

日期：2026-10-13。基于用户确认的六项交互方向，在已完成的 Web MVP 上实现。技术设计 V0.3、人设和原始素材保持原样；本文件覆盖初版文档中关于主动能力、工具范围和上下文机制的旧描述。

## 可以体验的内容

1. **工具能力可见**：11 个受限工具，包括观察房间、调灯、浇水、抽卡、揭晓/回答卡片、开始/取消倒计时、移向物件、查询时间与准备网页链接。物件效果由服务端执行结果更新。普通聊天鼓励结合当前环境采取有意义行动；不强制每句话调用工具。Mock 每次普通询问也会观察房间，明确是预设策略。
2. **自主探索**：默认关闭。手动开启后约 3 秒开始第一步，随后空闲至少 22 秒才调度下一轮。一次开启最多 6 步，每分钟服务端最多接收 3 轮，每轮最多 2 个工具。模型结合当前房间自行选择，也允许观察后安静待着。Mock 的顺序为照顾干燥植物、抽卡、调灯、移动、休息。
3. **交互环境**：台灯开关、冷暖与亮度可视化；植物湿度与防重复浇水；4 张有限题库的发现卡；10 秒演示/一分钟休息沙漏；角色整体移向物件附近。没有新增图片依赖，物件由 SVG/CSS 绘制，角色继续使用原 512px 派生素材。
4. **常驻建议**：即使已有聊天，输入框上方仍保留建议；卡片未揭晓时提供答案选项。生成中增加「简短一点」「让我猜」「先停一下」。建议通过同一事件入口执行，可以打断当前输出。
5. **部位点击**：头顶、脸颊、徽章、手分别发送结构化事件；本地即时表情反馈，随后模型自然回应。Pixi 逆变换定位 + 当前贴图 alpha 排除透明区域；拖动和轻点区分，500ms 点击节流，220ms 合并。使用 Pointer Events，适配鼠标和触屏输入；实际自动化验证为桌面指针，未声称已做真机触屏测试。
6. **实时打断**：输入框不因生成而禁用。新消息/建议/点击先取消旧轮，再发新轮；保留实际收到的部分文本、工具调用结果、房间状态和中断标记。模型后续可接着说，已完成动作不回滚。重试只请求继续，不重放点击。

## 会话与运行约束

- 新页面创建随机会话，服务端内存记录消息与房间。清空删除旧会话；刷新创建新会话并请求删除旧会话。页面卸载的删除是 best effort，漏删会话在闲置一小时后、下次访问 store 时清理。最多 64 个会话，无磁盘聊天保存。
- 上下文按完整交互轮剪枝：最多最近 16 轮、约 30000 个 JSON 字符；每次开始新轮时清理旧轮，当前轮单条用户文字最多 4000 字。工具调用和结果成对保留。不是长期记忆，也不保证记住已被剪掉的旧内容。
- `/api/sessions` 创建/删除会话；`/api/interact` 使用 `sessionId + requestId + input`；中断接口带 `visibleChars` 修剪未收到的文字。初版 `/api/chat` 为原测试保留，当前 UI 使用新端点。
- `requestId`、AbortController、当前轮检查和场景 revision 共同阻止旧请求回写；服务端拒绝近期重复 ID，校验工具参数、卡片 ID 和倒计时到期。已完成的真实效果不会因断流丢失。
- 普通轮最多 4 次工具执行；自主轮最多 2 次；60 秒截止时间；新交互端点最多同时 6 个请求。模型重复工具 ID/超限在写入上下文前拒绝，避免留下缺少工具结果的消息。
- 输入框有待发送文字、正在生成、页面隐藏时，不启动自主轮。用户发送立即优先；关闭自主开关只取消自主轮，不取消正在响应的用户请求。任一自主失败停止自动探索。6 步结束后需再次手动开启。
- 倒计时使用实际截止时间，不会每秒调用模型；完成后页面可交互时发送一次环境事件。隐藏/关闭页面不能提供系统通知；页面忙时完成提示延后。植物湿度暂不随时间衰减。
- 房间快照和工具消息是实际事实来源。表现仍是整体 sprite 与轻微动作，不增加无素材支持的眨眼、挥手、骨骼动画。部位热区是近似几何范围配合 alpha 命中，并非逐部位分割模型。

## 演示顺序（约两分钟）

打开 `http://127.0.0.1:5173`，先选演示模式保证固定效果：

1. 关灯、重新开灯、换暖光，展示工具卡片与环境同步。
2. 点盆栽；回复开始后直接点「简短一点」，展示已浇水不会撤销或重复。
3. 点发现卡，点击答案；随时可以说「让我猜」或换卡。
4. 点角色头顶、脸颊、徽章、手，观察不同回应。
5. 点「试试 10 秒」，等她主动回应倒计时结束。
6. 清空后开启自主探索，等待第一步自动浇水，再用消息或点击接管。
7. 切换真实模型，让 Step酱自行选择如何回应和使用工具。

此阶段未实现声音；2026-10-14 后续已接入 TTS / ASR，见 [语音接入记录](AUDIO_INTEGRATION.md)。更多物件、长期偏好和真实局部动画仍可后续扩展。

## StepFun 官方接口切换

2026-10-13：默认接入改为 `https://api.stepfun.com/v1`，模型仍是 Step 5 Preview，官方 ID 为 `step-5-preview`；OpenRouter 对应 ID 是 `stepfun/step-5-preview`。根目录 `.env` 保留原 OpenRouter 密钥与模型配置为注释，实际密钥不进入仓库。

`LLM_PROVIDER=stepfun` 读取 `STEPFUN_API_KEY` / `STEPFUN_MODEL`；切换为 `openrouter` 后读取原环境变量。两套服务使用固定地址、独立密钥和各自推理参数：官方 `reasoning_effort: low`，OpenRouter `reasoning: { effort: low }`。没有自动跨服务回退。

官方实测发现工具参数续片带 `type: ""`，解析器已兼容并增加回归测试。28/28 测试通过；官方模型列表确认模型可用。实际 API 验证了浇水、中途打断、上下文保留且不重复浇水，以及自主调灯和抽卡。最新调用证据保存在被忽略的 `artifacts/interaction-live.json`，之前 OpenRouter 实测结论仍为当时记录。
