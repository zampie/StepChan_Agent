# 实施阶段与验收清单

> 这是保留的开发前验收清单。2026-10-13 实际实现与证据见 [VALIDATION.md](VALIDATION.md)，设计调整见 [IMPLEMENTATION_NOTES.md](IMPLEMENTATION_NOTES.md)。

这些是待实现的验收条件，不是本启动包已经通过的应用测试。建议接手 Agent 在每条旁记录结果、运行命令和证据路径。

## M1：真实角色可展示

建立 React/TypeScript/Vite/PixiJS 8 工程、资产加载和基础调试页。交付 neutral、六种表情手动切换、轻微 idle；页面内拖动归 P1，可在本阶段顺手完成或延后 M5。

- [ ] 原 manifest 与图片复制路径正确；没有加载不存在的 base/neutral.png。
- [ ] 角色等比显示，底部锚点固定；图片失败可解释且 neutral 也失败时显示故障面板。
- [ ] React 开发重复挂载/卸载不增加 canvas、ticker 或监听器。
- [ ] 全部图片通过存在性、尺寸、alpha 和 manifest 路径检查。

## M2：表现与中断可验证

实现 PetController、idle/think/bounce/talk 和三通道约束，完整 debug 页。

- [ ] 六整身表情互斥显示，无重影；配准问题有截图记录。
- [ ] neutral 下逐张试嘴型；其它五表情强制隐藏嘴型。
- [ ] 开/闭嘴无双嘴、矩形接缝和明显肤色跳变；不合格则关闭 capability 并记录降级。
- [ ] bounce 一次结束恢复基线；连续触发/取消不漂移，无旧回调回写。
- [ ] 页面隐藏及减少动态模式正确处理，停止/销毁不残留嘴型循环。
- [ ] 未提供的 blink/wave 不进入可执行动作列表。

## M3：Mock 与真实对话

先用 Mock 覆盖所有事件，再接 Node/Fastify 及单个真实 Provider。不得让获取密钥阻塞 Mock 开发。

- [ ] 输入→listening，提交→thinking，文本→speaking，终态→idle。
- [ ] 多轮历史在内存里工作；清空/刷新后消失；不隐式存储聊天。
- [ ] SSE 覆盖拆帧、合帧、中文多字节、心跳、非法 JSON、非法表现枚举。
- [ ] 取消、超时、断流、重复 done、迟到旧 requestId 不破坏新请求。
- [ ] 服务端错误不暴露密钥；错误后能再次发送；中断的部分文本明确显示未完成。
- [ ] 真实 Provider 至少完成两轮上下文对话；缺少凭据时注明未验证。
- [ ] 前端构建产物与网络请求不包含模型 API Key。

## M4：两个受限工具

- [ ] get_time 返回真实时间及明确时区；无效时区有错误，缺省明确回退。
- [ ] open_url 返回提案卡片，用户点击前零次自动打开；回复不宣称已打开。
- [ ] 拒绝 javascript/data/file、带账号密码的 URL 及未注册工具。
- [ ] 工具调用次数有上限，同 toolCallId 不重复执行；错误后继续可交互。
- [ ] 模型只有实际收到工具结果后才能描述结果，不预播“完成啦”。

## M5：人设与演示打磨

- [ ] 拖动在页面边界内，取消旧动作，缩放页面后角色仍可找回。
- [ ] 初次见面自然自我介绍；被指出错误先修正；任务失败说明真实问题。
- [ ] 用户难过时不继续强行调侃；默认不称“主人”；一次最多主动扩展一个话题。
- [ ] 无交互时安静，不使用“你怎么不理我”等索取关注话术。
- [ ] 主动闲聊默认关闭；若实现开启模式，测试输入/忙碌/隐藏页面/未回应时抑制。
- [ ] “星星笔记”不落盘，不假装已有记忆、提醒或其它窗口读取。
- [ ] typecheck、必要单测、生产构建通过；README 记录版本、命令和环境配置。

## 最小演示流程

启动 Mock → 查看角色待机 → debug 切换六表情 → neutral 嘴型检查 → bounce/think → 输入并看到流式回复 → 中途停止再发新问题 → 模拟失败恢复 → 时间查询 → 网页链接提案并点击 → 清空会话 → 切真实模式完成两轮对话。

建议自动化重点：控制器转移、嘴型约束、取消与迟到事件、SSE 解析、工具 schema、时区、URL 协议和调用上限。人工重点：真实尺寸下配准、边缘、嘴型与自然度。只有上述各类证据齐全才能称应用验收完成。
