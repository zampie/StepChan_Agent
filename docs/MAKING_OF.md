# Step酱 制作过程备忘

一个 AI 桌宠从 Web MVP 到可分发 macOS 应用的全过程记录。**写给以后的项目看**，
所以重点不是"做了什么"，而是**哪些方法真的管用、哪些判断事后证明是错的**。

全程由 AI agent 开发（人只提需求与验收），所以这份文档也是一份 agent 协作的实践记录。

## 二、目标与中途的取舍

最初的四个方向（人给的）：

1. **实时响应** —— ASR/TTS 串行链路太慢，换更快的模型或走 realtime
2. **美工** —— 每个表情一张独立静态图、切换生硬，要能平滑过渡
3. **桌面化** —— Web 版受浏览器约束，用 Tauri 2 做透明背景桌宠，预留 Android
4. **打破第四面墙** —— 让她能感知系统与用户

### 做对的取舍

**realtime 替掉串行链路。** 一条 WebSocket 承载听/想/说/调工具，说完到首帧音频
实测中位 **235 ms**（最快 7 ms）。旧版按句合成，句间必须等。

**分层是算出来的，不是声称的。** 每个表情变体与基准图做像素 diff，变化区域紧凑的
裁成配准覆盖层，不紧凑的降级为整图交叉淡入 —— 并且**把降级原因写进 `rig.json`**。
11 个表情里 8 个真分层，3 个（害羞/生气/难过要画腮红、怒气符号、眼泪）降级。
10 个动作里 9 个有独立姿势，`tilt` 三版 prompt 都没让模型真的歪头，改由渲染器
对整身图转 12.6°。

> 这件事的价值在于：**"哪里没做到"被写成了数据而不是留在某人脑子里**。后来写
> README 配图脚本时，正是靠 `rig.json` 的 `degraded` 列表才没把降级项说成分层。

**程序化动画而不是堆逐帧素材。** 呼吸、随机眨眼（带偶发连眨）、摇摆、拖拽的挤压
拉伸与惯性、落地回弹、150 ms 表情交叉淡入、口型由播放音频的 RMS 驱动。素材只有
39 张 PNG，动起来的部分全是算的。

**感知能力全部默认关闭，并且拒绝时要说清楚。** 关着的时候她明确说"你得先打开那个
开关"，而不是假装看不见 —— 这是产品决定，也避免了"功能静默失效"这类最难查的问题。

### 砍掉的东西

**语速调节。** 做过播放侧 WSOLA 时间伸缩（音高保持得很好），但 realtime 下加速是在
和数据率打架：模型大致按实时出音，按 r 倍消耗就得垫住 T·(r−1)/r 的音频才不断续
（实测 1.15× 要垫 480 ms）。上游恰好 1× 实时时，**加速一点时间都省不下来** ——
省的只是"她说话的语速"，换掉的是"她多久开口"。人试过之后判定延迟不可接受，整个移除。

> 后来清理时发现这套代码（约 400 行 WSOLA + 弹性倍率）**完全没有调用方**，
> 注释还引用着已删除的设置项。删除前做了逐样本等价性验证（见第四节）。

**"小房间"与房间道具。** 推翻重做时删掉，换成面向桌面的能力。

## 三、Agent 开发流程

### 3.1 多 agent 分工：三个真实案例

**案例一：独立评审（最高回报）**

人问"你要不要启动一个评审用 subagent"。派一个 agent 只做审计、**不许改任何文件**，
产出缺陷清单，要求每条给 `文件:行号`，并**区分"确凿缺陷"与"可疑之处"**。

结果：12 条确凿 + 7 条可疑。更重要的是它自己写了一次性脚本，用真 `RealtimeSession`
+ 假 WebSocket 把关键假设跑了一遍，标注"已实跑验证"。其中几条是我自己改了一周
都没看见的：

- `busy` 判据写成 `activity !== 'idle'`，而持续聆听下她空闲时是 `'listening'`
  → busy 永久为真 → 点她只换表情不开口、主动感知整层静默。**两个无声失败**
- 设置窗改的东西根本没应用到当前会话（三条写入路径只有一条生效）
- 用瞬时 RMS 判断"她在说话"，欠载那一瞬会被判成没在说话 → 打断门控失效

**为什么有效**：审计者没有"这是我写的"的包袱，而且被明确要求给证据。
让同一个 agent 既实现又评审，它会倾向于确认自己的设计。

**案例二：并行修复（要靠文件所有权约束）**

评审结论跨两组文件且互不重叠，于是：我改语音状态机（`RealtimeSession.ts` /
`SpeechStream.ts` / `shared/realtime.ts`），另派一个 agent 改 UI 层（`App.tsx` /
`Bubble.tsx`）。给它的指令里有一段硬约束：

```
你只能改这些文件：…
绝对不要碰（我正在同时改，改了会冲突）：…
如果你认为某个修复必须改我的文件，不要改，在报告里写清需要什么，我来做。
```

还预先约定了跨边界的契约：「我会在会话层保证，需要清空用户气泡时发
`{type:'user_transcript', text:'', final:true}`」。这样两边可以真正并行而不是
互相等待。

结果：零冲突。它还主动越界建了一个新文件（`ui/uiState.ts`）并在报告里说明原因
（纯函数必须放在能被 node 测试 import 的地方），这是正确的越界 —— 新建文件不冲突。

**案例三：大段删除 + 等价性证明**

删掉失效的变速实现（约 400 行 worklet + 753 行测试）派给了 agent，指令里要求：

1. **先验证"真的没有调用方"，别只信我说的**
2. 保留清单（哪些是原速路径在用的，删了会出声音问题）
3. 实测结论要压缩进注释保留，不要一删了之
4. 删测试之前**先挑出其中只测原速路径的**搬走，别连带丢掉覆盖

它交回来的东西超出预期：除了代码，还做了**逐样本等价性验证** —— 把删前删后两份
worklet 并排驱动（4 组采样率组合、中途 flush、制造溢出），140 万个输出样本零差异、
约 2800 条 postMessage 逐条一致。

### 3.2 失败案例

**一个 agent 跑了 24 分钟、烧掉 146k token、产出零代码。** 它一直在"规划与编译"
之间循环。恢复时加了一条指令：**先把文件写出来再去编译**。

教训：给 agent 的任务里要有可验证的中间产物。"实现 X"不如"先写出文件 A/B/C，
再跑编译"。

### 3.3 给 agent 的指令里什么真的管用

| 指令 | 为什么 |
|---|---|
| 「每条结论必须给 `文件:行号`」 | 无法给出位置的结论通常是幻觉 |
| 「区分确凿缺陷与可疑之处，不确定就标后者」 | 不这么要求，它会把猜测写成缺陷来凑数 |
| 「只评审，不要修改任何文件」 | 审计与实现混在一起会让它边改边自我确认 |
| 「你只能改这些文件 / 绝对不要碰这些」 | 并行时唯一可靠的冲突预防 |
| 「先写文件再编译」 | 防规划死循环 |
| 「没有证据的猜测不要进清单」 | 本项目在读码推测上错过多次 |
| 「如果失败的不是你的文件，别管，在报告里说」 | 并行时别让它去修别人正在改的东西 |

### 3.4 提效的真实来源

不是"同时写更多代码"，而是：

- **评审并行于开发** —— 审计 11 分钟跑完，等价于一次完整的 code review
- **大段机械工作外包** —— 删除 1360 行 + 做等价性证明，主线完全不受影响
- **互不重叠的修复并行** —— 两组文件同时推进

反过来，**不该并行的情况**：同一个文件、或需要共享中间判断的任务。强行并行的
代价（约定契约、处理越界、合并验证）会超过收益。

## 四、Bug 排查方法论

这是这个项目最值得带走的部分。

### 4.1 主要敌人是"无声失败"

这个项目的 bug 大半**不报错，只是功能不发生**：

- 开关点了没反应（设置的 Rust 白名单漏了 6 个键，前端写入被静默丢弃）
- 点她只换表情不说话（`busy` 判据错，`narrate()` 每次都走"她在忙"跳过）
- ASR 气泡永久卡住（清空路径只剩一条，而那条在默认配置下是死代码）
- 活动状态卡在 `thinking`（永久三点气泡 + 点她不说话 + 主动感知整层静默，零报错）
- 桌宠完全不可见（三个原因叠加，而 `catch {}` 把关键异常吞了）

**所以：`catch {}` 是这个项目最贵的一行代码。** 它让"桌宠不可见"的排查成本
从几分钟变成几小时。后来定的规矩是：吞掉异常必须写明为什么吞、以及吞掉之后
用什么别的方式让人知道。

### 4.2 诊断通道必须早建

桌宠窗没有地址栏、没有控制台，WKWebView 的 `console` 也不进进程 stderr。
结果是前端任何失败（素材 404、CSP 拦截、WebGL 不可用）在打包产物里**完全不可见**。

于是加了一条通道：`reportDiagnostic` → Tauri 命令 `log_frontend` → 进程 stderr。
从终端启动 `.app` 的二进制就能看到。

**这条通道后来定位了 v2.0.1 的全部四个 bug。** 它的价值在一次对比里体现得最清楚：

> 排查"睡觉时点一下没反应"，我**连续两次靠读代码推测根因**：
> 第一次猜"表情图层被 `layersActive()` 隐藏了"，第二次猜"渲染循环在睡觉时停了"。
> **两次都错。** 第三次改用 headless 夹具驱动真实渲染器打印状态，一次定位：
> 洗牌袋抽到了 `head.sleepy`（困倦脸 + zzz），她刚被叫醒就又摆回困倦 —— 看起来
> 和没醒一样。
>
> 同一天排查"关了开关还是被打断"，真机日志直接给出答案：
> ```
> vad: 服务端检测到人声开始
> vad: 不可打断 —— 已暂停音频上行并清空服务端缓冲   ← 确实执行了
> asr: 转写完成「」                                 ← 音频真的被清掉了
> turn: 服务端开始生成回复                           ← 服务端照样开了新回合
> ```
> 四行日志否掉了我写在代码注释里的一个推断，而那个推断读代码是看不出错的。

**结论：能拿到真实运行数据时，不要靠读代码推测根因。** 代码告诉你"应该怎样"，
日志告诉你"实际怎样"，而 bug 恰好活在两者的差里。

### 4.3 测试必须验证"还原修复即报红"

写完回归测试之后，**把对应的修复还原，确认测试真的报红**。

这一步抓出了三条假测试：

- 两条没把 bug 的真实现场摆出来。旧判据是 `responseActive || audioLevel > 0`，
  只满足一个条件时它照样认为"她在说话"，所以测试在修复前后都绿
- 一条断言写成「最后一次 activity 不是 `thinking`」，而旧代码**压根不发事件** ——
  断言对着 `undefined` 平凡通过

> 一条在修复前后都通过的测试，比没有测试更糟：它让你以为这里被盯住了。

还有一条测试**本身就编码了错误的模型**：它断言"收到人声检测后要发
`input_audio_buffer.clear`"，而真机日志证明这个做法根本来不及。修法变了，
那条测试就该重写而不是保留 —— 测试是对行为的断言，行为的前提错了，断言也要换。

### 4.4 大改动要有等价性证明

删掉 612 行 worklet 代码时，用的不是"跑一遍测试看绿不绿"，而是：
删前删后两份实现并排驱动，**逐样本比对**。4 组采样率组合、61 万个输出样本零差异、
`level`/`started`/`drained`/`overflow` 四种上报逐条一致（含顺序）。

这个验证做了两轮 —— agent 验了它那一版，我在它之上又删了一批只写不读的状态，
于是重新验了一次。

### 4.5 用一次性脚本做确定性复现

两次关键定位都靠它：

- 评审 agent 写脚本用真 `RealtimeSession` + 假 WebSocket 回放事件序列，
  复现了"重连后 ASR 气泡卡住"等 7 条
- 排查睡觉点击时，用 `tests/rig.test.ts` 已有的 headless 夹具驱动真实渲染器，
  `console.log` 打印每一步的 `action` / `expression`，一次看出抽到了哪条反应

**现成的测试夹具是排查资产，不只是测试资产。**

## 五、反复出现的失败模式

### 5.1 两个真相源（出现了至少四次）

| 同一个事实 | 两处定义 | 不一致的后果 |
|---|---|---|
| 设置的形状 | zod schema / Rust 白名单 | 前端写入被静默丢弃，开关点了没反应 |
| 音色清单 | 设置窗 / 托盘菜单 | 同一个音色两个中文名（「活力轻快」vs「轻快爽朗」） |
| 持续聆听开关 | `Brain.settings` / `RealtimeSession.options` | 漂移后长按说完松手什么都不发生 |
| 几何参数 | 渲染器 / 配图生成脚本 | 配图比应用本身还错（睡觉姿势眼睛飘到头顶） |

**对策**：能合并就合并（音色清单收到 `shared/desktop.ts`，VAD 参数抽成单一常量）；
跨语言合并不了的，**写测试解析另一侧的源码逐项比对**（`tests/settings-parity.test.ts`
直接解析 Rust 的 `defaults()`）。解析源码很脆弱，但"宁可将来有人改了写法导致测试报错，
也不要再出现一次加了键但没生效"。

### 5.2 反应式处理来不及

「不可打断」的第一版是：收到服务端的人声检测事件后停止上传音频并清空缓冲，
推断"没有音频就没有回合"。真机日志否掉了它 —— 服务端在**发出事件的那一刻**
就已经开了回合，事后清缓冲救不回来。

改成预防式：她一开口就把 `turn_detection` 热改成 `null` 把服务端 VAD 整个关掉，
说完再恢复。

**模式**：当对手（服务端）的状态机在你收到通知时已经前进了，补救性操作必然太晚，
只能改成提前阻止。

### 5.3 文档与实现漂移

README 写着"她说到一半你开口，她会立刻停下" —— 而「允许说话打断她」**默认关闭**。
这是用户一上手就会撞的错误描述。类似的还有：

- 写着"右键 → 打开"绕过 Gatekeeper，而 Apple 从 macOS 15 起**删掉了这条路径**
- 写着"停止上传并清空缓冲，没有音频就没有回合"，而这个推断已被真机否掉
- 写着"点一下她再试"，而当时**没有任何代码会真的重建连接**

**对策**：每次改了行为就去搜文档里的相关描述。留着一个错误的机制描述比没有描述更糟。

### 5.4 我自己造的回归

修「不可打断」时，把"关掉服务端 VAD"和"掐断音频上行"拆成两次调用，
**只给前者加了"可打断就跳过"的闸门** —— 于是开着打断开关时她一开口就停传音频，
服务端听不到用户说话，**打断功能整个失效**。

这是人报回来的。修法是让两者共用一个闸门，并把真机日志抄进注释防止再被拆开。

**教训**：把一个带条件的操作拆成多步时，条件必须跟着一起拆或者提取成共用闸门。

## 六、踩坑清单

### Tauri / macOS

- **CSP `script-src 'self'` 阻止 Pixi 的 `new Function()`** → 必须 `import 'pixi.js/unsafe-eval'`
- **资源路径**：Pixi 把 `/rig/rig/base.png` 解析成 `tauri://rig/rig/base.png` → `resolveBaseUrl` 返回绝对 URL
- **`.env` 用相对路径找不到**：Finder 启动的 `.app` 的 cwd 是 `/` → 候选路径必须绝对（exe 祖先、cwd 祖先、`~/.stepchan/.env`）
- **entitlements 不生效**：Tauri 在没有 `signingIdentity: "-"` 时会跳过它们
- **`ActivationPolicy::Accessory` 下 `set_focus()` 不激活进程** → 输入框打不进字，要 `setInteractive(true)` + 激活应用 + 激活后再 focus
- **TCC 权限绑定代码签名**，ad-hoc 签名每次重建身份都变 → 麦克风授权反复失效。演示前的正确顺序：构建最后一版 → 在那个产物上授权 → 不再重编
- **Gatekeeper**：ad-hoc 签名 + 未公证，`spctl -a` 返回 `rejected`。**macOS 15+ 没有"右键 → 打开"了**，只能走 系统设置 → 隐私与安全性 → 仍要打开，或 `xattr -dr com.apple.quarantine`
- **`screencapture` 失败时退出码仍是 0**，错误只写 stderr → 判据只能是"产物存在且非空"

### 语音协议（realtime）

- **鉴权必须走 subprotocol**：webview 设不了 `Authorization` 头，query param 形式被拒
- **用户语音转写的 delta 是「累计全量文本」不是增量**，而她自己的字幕流是增量 ——
  两者不对称。用 `+=` 会把一句话叠成好几遍
- **`response.cancel` 有尾巴**：取消后还会到 4 条在途音频增量，不拦就会在被打断后
  又蹦出半个字
- **服务端 VAD 在发出人声检测事件的那一刻就已开了回合**（见 5.2）
- **`turn_detection` 可以在同一连接上用 `session.update` 双向热改**，改完立刻生效 ——
  这条实测记录救了「不可打断」
- **协议缺口**：没有"要 VAD 断句但不要自动开回合"的字段
- **PCM 采样率 24000 文档没写**。确定方法是测服务端自报的 `audio_end_ms` 在两种
  缓冲长度下的**斜率**以抵消 VAD 偏移；单点读数不可用，而"时长对比文本长度"
  这种启发式会给出错误答案（同一音色同一文本的语速能差 2 倍）
- **空闲会话会被服务端掐掉**（`too long without operation`），自动重连，但不该把
  这条当错误弹给用户

### 美术与生图

- **`/images/generations` 能出透明背景，`/images/edits` 完全忽略 `background=transparent`**
  （HTTP 200 但产物是 RGB 无 alpha）→ 变体派生走"纯品红幕布 + 本地抠色"（实测晕边 0.35%）
- **模型给的主体 alpha 上限只到 253–254**，没有真正不透明的像素，严格合成要自己阈值化
- **筛选候选必须在真实显示条件下做**：缩到 220 px 放在浅色和深色底上比。同样条件下
  `high` 相对 `medium` 看不出差别，所以变体一律用 `medium`
- **模型渲染中文几乎必糊** → 海报的做法是"模型只画背景，角色用真素材、文字用真排版"
- **模型不会画出你已有的角色** → 同理

### 工具链

- **Chrome 的 `--screenshot=` 不展开 `~`**，写不进去也不报错（我因此交了一版旧海报）
- **`file://` 下 `fetch` 被 CORS 拦掉**，页面不报错但数据没来 → 必须走本地 HTTP
- **bash 变量名后紧跟多字节字符**（如 `$FRAMES（`）时，某些 locale 下首字节被当成
  标识符字符 → 变量名被污染成 `FRAMES\xef`，报 unbound variable。**后跟非 ASCII 一律 `${VAR}`**
- **node 的 `console.log` 对数字会上色**，ANSI 码混进命令替换会把算术表达式弄炸 →
  用 `process.stdout.write(String(n))`
- **heredoc 会吞掉行尾的 `")`**（遇到过一次）→ 复杂引号用脚本写文件而不是 heredoc
- **`lark-cli` 的附件必须是相对当前目录的路径**，而 `--dry-run` 不校验这一项

### Git 与分发

- **误提交 `target/`**：一个提交里 3477 个文件、1047 MB，其中单个 `.rmeta` **109.8 MiB
  超过 GitHub 的 100 MiB 硬上限** → push 必定被拒（而且是先传完几百 MB 再拒）。
  清理后 `.git` 从 316 MB 降到 70 MB
- **`git add -A` 会把别人工作区里的东西一起扫进来**。我因此把一个无关工具提交进了
  历史，后来要做一次历史改写才清掉。提交前看一眼 `git status`，或者点名加文件
- **120 fps 录屏的码率绝大部分耗在帧率上**：37.7 MB → 1.5 MB 只需降到 30 fps + CRF，
  **分辨率不用动**
- **GitHub 的 markdown 不会把仓库里的 mp4 渲染成播放器**（`<video>` 的 src 被限制在
  特定域）→ 内嵌只能用 GIF，mp4 走链接

## 七、真正难的几件事

**1. 实时语音状态机的并发与乱序。** 服务端会在一轮还没收尾时自己开下一轮，两轮的
事件真的会交错；迟到的 `response.done` 会把新一轮判成已结束。最终需要：对 response id
做身份校验、统一的"放弃当前回合"复位、以及一个看门狗兜住 `speaking` 和 `thinking`
两个可达的死状态。**这一类 bug 没有稳定复现路径，只能靠不变量 + 看门狗 + 日志。**

**2. "不可打断"这个看似简单的开关。** 它最终需要三处配合：客户端不做本地打断、
预防式关掉服务端 VAD、掐断音频上行。而且这三处必须共用一个闸门（见 5.4）。
根因是协议缺口 —— 如果有 `create_response: false` 这个字段，整段逻辑可以删掉。

**3. 分层配准。** "把表情拆成可叠加的图层"听起来只是美术问题，实际要解决：
变体与基准图的像素 diff、变化区域是否紧凑、不紧凑时怎么优雅降级、以及
**覆盖层在哪些姿势上成立**（整身图自带脸，再叠覆盖层会让眼睛飘到头顶）。

**4. 透明窗口的点击穿透。** 透明区要穿透到下层应用、角色身上要能点能拖，而且
命中区要随姿势变化。最终是 Rust 侧轮询光标位置 + 前端上报逐姿势命中区。
输入框和拖放落点在命中区之外，还要能强制进入交互态。

**5. 让"没做到的部分"可见。** 这是贯穿全程的工程主题：降级原因写进 `rig.json`、
未验证项写进 `PROGRESS.md` 与 `docs/TODO.md`、拒绝执行时明确说出缺哪个开关。
**代价是文档维护成本，收益是后来者不会把"没做"当成"做了"。**

## 八、如果重来

1. **第一天就建诊断通道。** 它定位了后期全部的真机 bug，而前期"桌宠不可见"
   那次排查了几小时 —— 如果当时有它，几分钟就能看到 CSP 异常
2. **第一天就立 parity 测试。** "两个真相源"出现了至少四次，每次都是静默失败
3. **回归测试写完立刻做"还原即报红"验证。** 这一步抓出了三条假测试，成本只有几分钟
4. **`catch {}` 一律当成待办。** 每一个都要么补上报，要么写清为什么可以吞
5. **不要在没有真实数据时推测根因。** 两次推测、两次错。拿日志或写一次性复现脚本
6. **评审交给独立 agent，并要求它给证据。** 这是整个流程里性价比最高的一步
7. **提交前看 `git status`。** 一次 `git add -A` 换来一次历史改写

## 附：这个项目本身的"原生 AI"成分
